# time tracking app

the first and foremost: reduce the user input friction
the draft starts from making a web prototype; ending to targeting multiple platforms
use mode to switch different context: past, now, future

use ring menus to activate commands like a breeze
use configuration page to setup ring menu items

users may go strict or lenient on input

## principles nega

no need to make extreme UX at this point...
no need to provide too many data manipulation tricks
avoid micro-management at all cost
however, macro-management is allowed

## principles

avoid start/ stop repeatedly. it's annoying.
however, start/ stop is probably the easiest UX we can have...
just let users to the right thing

we could make nesting timer. however, it's again too complicate

divide the day into several sections
the left most button is the one to give meaningful tags on an time entry; it is a ring menu
the second button would be the start/ stop button

options for always create a new time entry per stop (defaults to true)
users may hold the start/ stop button for an non-idempotent action to merge the time entry (please don't)

prefer lenient over strict
prefer macro over micro

## interesting features

add a clock and stop the timer automatically

## data manipulation cases

levels of forgetter

- the timer didn't run at all
  - insert data for the past
  - insert data for the future
- the timer did run (now)
  - start time earlier?
  - end time earlier?
  - arbitrary task in-between

- I forgot to start the timer. make the start time a bit earlier
- I forgot to stop the timer. make it ends time a bit earlier
- I need to insert some other task in-between the current timer for some reasons

## case 1: predefined tasks

tasks are predefined with a start time
for mode 'now', load up the current task automatically on the screen
you can predefined the estimation duration of the task
which would affect how lenient input works

### accurate strict input

this mode, time are accumulate
the only interaction is to start and stop a timer
possible UI controls
- tap to start and stop
this should be very similar to how "Toggl" works

### accurate lenient input

if users forgot to set the timer, it is possible to enter the time manually
possible UI controls
- a slider with clear predefined steps
- a number input
- a ring menu with predefined items

users should predefined steps of a task
if not, defaults to 15, 30, 45, 60 min

possible operators
- value assign
- value addition

### loose lenient input

if users forgot to set the timer, it is possible to enter the endtime directly
possible UI controls
- a datetime input
- tap to use current timestamp as endtime
