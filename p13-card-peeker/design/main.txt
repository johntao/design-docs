# card-peeker

this application aim to create an interactive card visualizer
the app consist the following modules:
- canvas (a.k.a. something similar to the root of a file system)
- side panel
- visual component (a.k.a. the card)
- the dataset
  1. top-down items (a.k.a. something similar to folders)
  2. bottom-up items (a.k.a. something similar to file)

## side panel

list all bottom-up cards here
the user can drag and drop bottom-up cards into a top-down card
dropping a bottom-up cards into a top-down card would create bi-directional links between the two cards

## cards

the cards are rendered in the canvas, representing items loaded from the dataset
in our first implementation, let's add a few constraints to make things as simple as possible
1. forbid rendering a bottom-up item in the root directly (i.e. only folders are allowed in the root)
2. nest two layers of top-down items at max (e.g. `dir1/dir2/file` is allowed; `dir1/dir2/dir3/file` is forbidden)

### function
the basic functions of a card:
- load items from dataset, render these items as cards in the canvas
- a card is a rectangle which display two fields of an item
  - show the title on the top section of the card
  - show the content on the bottom section of the card
- top-down cards may consist other top-down cards or bottom-up cards
  - bottom-up cards cannot fit into a top-down card with folder depth value of an odd number
    - e.g. `dir1/dir2/file` is allowed; `dir1/file` is forbidden
- click on a top-down card trigger navigation similar to open a folder
  - redraw the canvas, show the content inside the card
  - create a link to navigate back to the root
- click on a bottom-up card trigger a popup displaying the content of the card

## rendering
how does the rendering work:
- the canvas render all the top-down cards that sit in the root at once
- top-down cards are rendered by two levels at once
  - put the parent folder in the center
  - put the children folder around the parent folder
  - connect a straight line between the parent folder and the child folder

## dataset

### top-down

top-down item fields:
- title
- content
- links

the folder relation is defined in the title

#### example

given an item with title `dir1/aaa` and an item with title `dir1/bbb`

which should create three top-down folders in the canvas (i.e. dir1, aaa, bbb)

`dir1` is the parent folder
`aaa` and `bbb` are the children folder

### bottom-up

bottom-up item fields:
- title
- content

the folder relation is defined in the title

#### example

given an item with title `dir1/aaa` and an item with title `dir1/bbb`

which should create three top-down folders in the canvas (i.e. dir1, aaa, bbb)

`dir1` is the parent folder
`aaa` and `bbb` are the children folder
